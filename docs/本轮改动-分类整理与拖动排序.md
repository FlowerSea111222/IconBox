# 本轮改动说明（0.9.20.16）

三块内容：① 空分类直接删除 ② 分类视图内图标可拖动排序 ③ 设置里的「自动清除桌面上已归类到面板的图标」。
另外修掉了拖动排序里两个会导致**图标重复 / 顺序错位**的真实缺陷。

---

## ① 空分类直接删除

之前的行为：分类里没有图标时，标签自动隐藏（分类本身还在配置里，越积越多）。
现在的行为：打开应用面板时，把所有 0 个图标的分类从配置里删除，并在状态栏提示「已删除 N 个空分类」。

改动位置：
- `source/src/IconBox/Controller.cs` — `RemoveEmptyCategories()`（约 :4582）
  原先的保护条件用了 `AppCategoryRules.IsBuiltIn(id)`，而内置集合包含全部 13 个默认分类，
  导致**任何内置空分类都删不掉**（功能实际不生效）。现在只保护「全部」。
- `source/src/IconBox/BoardWindow.cs` — 新增 `PruneEmptyCategories()`，在 `Open()` 末尾调用。
  带重入保护（`pruningCategories`），拖动中或面板未显示时不执行；跳过当前正在看的分类。

实测：往 layout.json 里注入 2 个空分类，启动后面板打开 → `CATEGORY prune empty n=2`，
layout.json 从 11 个分类回到 9 个。

## ② 分类视图内图标可拖动排序

改动位置：`source/src/IconBox/BoardWindow.cs` — 新增 `CommitReorder(string[] sequence)`。

- 「全部」视图：仍走原来的 `C.ReorderToSequence(sequence, page * capacity)`（按页切片写回）。
- 分类视图：走新的 `C.ReorderCategorySequence(activeCategory, sequence)`（`Controller.cs`）。
  因为 `Prefs.Apps` 是所有分类混排的全局顺序，过滤视图里同一页的图标在 Apps 中并不连续，
  所以不能按页切片；做法是「把这一页涉及的 Apps 槽位按新顺序重新填一遍」，
  其它分类的图标保持所在槽位不动 —— 只调整相对顺序，不跨分类搬运。

### 顺带修掉的两个缺陷（都会造成数据被破坏）

**缺陷 A：同一个 Path 被收录多条时，重排会复制条目、丢失原条目。**
`ReorderCategorySequence` 原来用 `Dictionary<string, Entry>` 按 Path 建索引，
同一 Path 的多个条目只会留下最后一条；写回时同一个 Entry 引用被塞进多个槽位。
实测症状：把 `Administrative Tools` 往右拖一格后，layout.json 里出现两条完全相同的 Path，
而 `Control Panel` 消失了。
修复：改用 `Dictionary<string, Queue<Entry>>`，按出现顺序**一对一**消费候选；
并加两道安全网（picked 集合去重后数量必须一致；picked 集合必须等于本页槽位集合）。

**缺陷 B：页首定位方式在拖动后失效。**
原来用 `sequence[0]` 去匹配分类序列里本页的起始位置。拖动之后 `sequence[0]` 已经是新顺序的第一个图标，
定位会失准甚至返回错误的 offset。修复：改用「本页 Path 集合 == 分类序列某一段的 Path 集合」匹配出 offset。

**缺陷 C：实时预览落点漂移（手感问题）。**
拖动时 `DragOver` 用 `Tiles.Children.IndexOf(tile)` 算落点，但这个集合已被上一次
`ApplyLivePreview` 重排过，连续 DragOver 会基于漂移后的顺序反复重算，
表现为「拖到第 4 格却落在第 3 格」。
修复：新增字段 `dragBaseOrder`，在拖动开始时冻结磁贴顺序；`BaseIndexOf()` 基于它算落点，
`ApplyLivePreview` 的 shift 计算也改用这份基准。

实测（真机，Win11 2560x1440 150%）：
| 测试 | 结果 |
|---|---|
| 「系统」分类：第 1 格 → 第 4 格 | 落在第 4 位，无重复（`Character Map, Command Prompt, Administrative Tools, Control Panel, ...`）|
| 「全部」视图：槽位 1 → 槽位 7 | 顺序正确，`dup=0` |
| 拖动后 layout.json | 无重复 Path，条目总数不变 |

## ③ 「自动清除桌面上已归类到面板的图标」开关

设置 → 通用 页，位于「自动隐藏 Windows 任务栏」之前。

改动：
- **新增文件** `source/src/IconBox/DesktopCleaner.cs`
  - `Apply(IEnumerable<Entry> apps)`：遍历桌面（当前用户 + 公共桌面），
    凡是已经被面板收录的项，**只把文件属性加上 Hidden**，返回处理数量。
  - `Restore()`：按历史记录把加过 Hidden 的项恢复。
  - 历史记录存 `%LOCALAPPDATA%\IconBox\desktop-clean-hidden.txt`，
    保证只还原「本软件加过」的项，不动用户自己隐藏的文件。
  - 跳过 `desktop.ini` 和带 `System` 属性的项；不递归子文件夹；**不删除任何文件**。
- `source/src/IconBox/Controller.cs`
  - `SetDesktopClean(bool)`（:347）：写 `Prefs.AutoCleanDesktopIcons` 并保存，开则 Apply、关则 Restore，状态栏提示数量。
  - `ApplyDesktopClean()`（:371）：启动时按开关状态执行一次（延迟到启动完成后，不阻塞 UI）。
  - 启动链里插入调用（:174）。
  - 设置页新增复选框（:2965）。

实测：打开开关 → 正好隐藏 5 项（全部 `hidden=True`），session.log 5 条 `DESKTOP clean hide`；
关闭开关 → 5 项全部恢复 `hidden=False`，`DESKTOP clean restore n=5`。
